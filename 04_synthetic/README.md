# 04_synthetic — 合成任务（机理验证）

元素从 $\mathcal{N}(0,I_8)$ 抽、组成由均匀随机数归一化得到（$w_k=u_k/\sum_j u_j$，$u_k\sim U(0,1)$，**不是 Dirichlet**），生成函数**由我们指定**，
因此可以把“组分数”与“交互强度”分开、把“未见组分”彻底排除。

## 脚本

| 脚本 | 内容 |
|---|---|
| `scripts/synth_routes.py` | 全部家族 + 两条路线，同脚本同数据（与原版逐字一致，只多一个 `--out`） |

## 这个实验回答什么

**一句话：即使目标函数是纯可加的，v(ex) 在组分数外推上仍然退化。**

这是最干净的归因——任务里没有任何交互、没有任何化学、没有任何未见组分，
生成函数在每个 $K$ 上完全相同，$K$ 只改变训练集的覆盖范围。因此退化只能来自
**聚合形式的估计性质**，不能推给任务本身。

**承担论证的只有一行：家族 A、$\lambda=0$。**

| K | v(im) | v(ex) | 差 |
|---:|---:|---:|---:|
| 3 | 0.9996 ± 0.0003 | 0.9847 ± 0.0009 | +0.015 |
| 5 | 0.9994 ± 0.0007 | 0.9341 ± 0.0007 | +0.065 |
| 10 | 0.9990 ± 0.0012 | 0.8556 ± 0.0033 | +0.144 |
| 20 | 0.9983 ± 0.0026 | 0.8062 ± 0.0074 | +0.192 |

三 seed 均值 ± 标准差，见 `runs/synth_add_pair_3seeds_summary.csv`；逐 seed 原始表为
`runs/synth_add_pair_s{42,43,44}.csv`（重跑命令见文末）。

v(im) 在全区间保持 0.998 以上（它只需学一个逐元素映射再线性加权），
而 v(ex) 从 0.985 单调掉到 0.806——**任务完全可加时仍然掉**。

## 为什么只用 add_pair、λ=0

**λ>0 会引入交互**，而交互本身就是 v(ex) 的“主场”——一掉就被质疑“任务变难了”。
只有 λ=0 才能把退化归因到聚合形式：任务没有任何交互，模型却仍然掉。

脚本里另有两个家族（`add_hidden`、`pair_hidden`）和 λ>0 的选项，正文未使用，结果也不在归档中。

## 协议

训练 $K\in\{1,2\}$，测试 $K\in\{3,5,10,20\}$；5,000 训练 / 2,000 测试；
3 seed（42/43/44）；300 epoch；Adam lr=$10^{-3}$、**无 weight decay**、batch 256（与化学任务不同）；
参数规模 30.2 k / 30.1 k（差 0.3%）。

## 重跑命令

```bash
for s in 42 43 44; do
  python scripts/synth_routes.py --families add_pair --lambdas 0.0 \
         --seeds $s --epochs 300 --out ../runs/synth_add_pair_s$s.csv
done
python scripts/collect_synth.py        # → summary.csv
```
